# @marinoscar/vault-api

## 0.1.0-next.6

### Minor Changes

- 63d94fc: Agent API: a purpose for saving a login the owner already signed in with (#233), agent contract 1.3 (additive, stability beta).

  - `@marinoscar/vault-contract`: `agentPurposeSchema` gains the value `save_login`, appended last (`login`, `signup`, `password_change`, `mfa`, `save_login`). It means "saving a login the owner already uses; send it with `POST /credentials`", is accepted wherever a purpose is, and is stored in the audit row like any purpose. `AGENT_CONTRACT_VERSION` moves from `1.2` to `1.3` and `AGENT_CONTRACT_FEATURES` gains `SAVE_LOGIN: 'save_login'`; the agent contract snapshot is refreshed (additive: a new enum value in a request, a new feature id). The conformance kit's fake Vault reports the feature in `whoami`.
  - `@marinoscar/vault-api`: `whoami.contract.features` always lists `save_login` (after `logins` and `totp`, before `cards` and `identity`). The create route is unchanged: the credential it creates is opened to agents for every purpose, a name already in use still answers 409, and the purpose `save_login` is recorded in the audit row.

## 0.1.0-next.5

### Minor Changes

- 36c152b: Cross-check a driver license's PDF417 (AAMVA) barcode, decoded in the browser (IDOC-11, #214). `@marinoscar/vault-contract/secrets`: `extractDocumentRequestSchema` takes an optional `barcode` (`documentBarcodeSchema`: `{ format: 'aamva', fields }` with the twelve `AAMVA_BARCODE_FIELDS`, each at most `DOCUMENT_BARCODE_FIELD_MAX_LENGTH` = 200 characters; unknown keys stripped), `extractDocumentResponseSchema` an optional `barcodePresent`; `DOCUMENT_CHECK_IDS` appends `aamva` and the Driver License kind declares it. `@marinoscar/vault-api/ai`: `CheckId` appends `aamva`; the ID document normalizer compares the barcode with the model's reading for a Driver License (the barcode wins on a mismatch, confidence 0.95, `BARCODE_WINS_WARNING`), adds the `aamva` check and returns `barcodePresent`; scan profiles receive `ScanRequestHints` (never sent to the model); `AAMVA_JURISDICTIONS` and `jurisdictionAgrees`. `@marinoscar/vault-web/documents/headless`: `parseAamva` (pure), `toDocumentBarcode`, `decodePdf417` (lazy-loads the new dependency `@zxing/library`, Apache-2.0, in its own chunk; never rejects), `readDriverLicenseBarcode`; `useDocumentScan` decodes the original back photo and exposes `barcodeOutcome` and `barcodeUnread`; the scan page shows a dismissible retake hint. All `@stability experimental`.
- d9947a8: Add the document check library for AI document scanning (IDOC-2, #205). `@marinoscar/vault-contract/common` gains the country table: `COUNTRY_TABLE` (ISO 3166-1 plus the ICAO 9303 codes `GBD`, `GBN`, `GBO`, `GBP`, `GBS`, `UNO`, `UNA`, `UNK`, `XXA`, `XXB`, `XXC`, `XXX` and the `UTO` specimen state), `COUNTRY_CODES`, `isCountryCode` and `toAlpha3` (alpha-2, alpha-3 or English name; the MRZ `D` maps to `DEU`). `@marinoscar/vault-api/ai` gains pure checks: `parseMrz` and `mrzCheckDigit` (TD1, TD2, TD3 with OCR repair of numeric positions), `checkSsn`, `checkVin` and `vinCheckDigit`, `normalizeDate` and `mrzDate`, `isMrzCountryCode` and the `CheckId` union. All `@stability experimental`.
- 831d238: Identity-document expiry reminders (IDOC-9). New subpath `@marinoscar/vault-api/document-expiry`: the server-only job `vault.documents.expiry_scan` (permanent type; 15 minutes, 2 attempts), its enqueue-only daily tick `DocumentExpiryTask` (05:43 UTC), and the pure `daysUntilDate`, `leadDaysFor` and `dueThreshold`. The scan reads only `expiry_date` and `document_kind` of Passport and ID Document secrets of active owners, notifies once per (document, expiry, lead day) through the new event `vault.document_expiring` (template `vault-document-expiring`, payload `VaultDocumentExpiringNotificationData`: id, name, label, expiry, days left, threshold; never a number, date of birth or holder name) and records the audit row `vault.document.expiry_notified` as the dedup record. New route `GET /api/secrets/documents/summary` (`secrets:read`, the caller's own documents) served by `DocumentSummaryService`.
- 114f55e: Passport and ID document scanning (issue #210, experimental): `POST /api/secrets/documents/extract` (`DocumentExtractController`, `DocumentExtractService`; the card route's guards: `secrets:write` + `ai:use` and the AI kill switch), the `passport` and `id_document` scan profiles (`createPassportScanProfile`, `createIdDocumentScanProfile`) registered by `createScanProfileRegistry` under the new permanent AI feature `DOCUMENT_EXTRACT_FEATURE` (`document_extract`), and the pure normalizer (`normalizePassportScan`, `normalizeIdDocumentScan`) that runs the MRZ, SSN and VIN checks. `VaultMetricsPort` gains `documentExtracted(documentType, outcome)` (implemented by `CountingMetrics`; a host binding the port must add it). `DOCUMENT_EXTRACTION_TYPES` joins the metric labels. A non-card scan logs "Document scan (<id>) unavailable" instead of the card wording. Persists nothing.
- 5d0d599: Generic document image roles and slots (IDOC-5). `@marinoscar/vault-contract/secrets` appends the attachment roles `data_page`, `front` and `back`, and adds `DOCUMENT_IMAGE_SLOTS` (Card: `card_front`/`card_back`; Passport: `data_page`/`back`; ID Document: `front`/`back`), `imageSlotsFor`, `imageSlotFor`, `isDocumentImageRole`, `documentNoun`, `ID1_ASPECT_RATIO` and `ID3_ASPECT_RATIO`; the errors slice adds `422 ATTACHMENT_ROLE_NOT_ALLOWED`. `@marinoscar/vault-api` refuses a role that is not an image slot of the secret's type on link and renew, applies the image MIME/size/signature checks to every document image role, names the slot in a duplicate-role 409, and orders and titles document images in the export from the slots (card output unchanged). `@marinoscar/vault-web` adds `DocumentImages` (`supportsDocumentImages`, `documentImageSlotsFor`, `findDocumentImage`, `documentImagesTypeName`): images stay hidden until revealed and are hidden again after the 30 s reveal timeout, when the browser tab is hidden or when the attachment changes; `CardImages`, `supportsCardImages` and `findCardImage` remain as aliases.
- ca2fec9: Field model (issue #206): `SecretsService` validates a `format: 'country'` string as an ISO 3166-1 alpha-3 code (upper-cased before validating, stored upper-cased; `isCountryCode` of `@marinoscar/vault-contract/common`) and a `keyvalue` value with `keyValueValueSchema` (a required one needs at least one entry) and stores the list as-is in the encrypted JSON; error messages name the field and entry, never a value. A data update equal to the current version's data (key order aside) no longer creates a version (`dataChanged: false`). MCP renders a `keyvalue` value as `label: value` lines, a sensitive entry as `label: [withheld]` (new `WITHHELD`), and reports every sensitive entry value to the fail-closed guard. The HTML export renders a `keyvalue` value as an escaped two-column table.
- ae1714a: Identity documents (issue #209): the metric label vocabulary `SECRET_TYPE_KINDS` gains `passport` and `id_document`. MCP never handles the `Passport` and `ID Document` system types: `isCardLikeType` is renamed `isMcpExcludedType` and excludes `Card`, `Passport`, `ID Document` and any cvv-like type from `list_secret_types`, `create_secret` (`TYPE_NOT_SUPPORTED`) and the get/update lookup. Agent access stays closed: opening either type to agents answers 422 `AGENT_ACCESS_UNSUPPORTED_TYPE`.
- 83a8e95: Scan availability by capability, not vendor (#213): `GET /api/secrets/scan/targets` (`ai:use`) and `ScanTargetsService` report the model each scan feature runs on with its catalogue capabilities, and `isScanAvailable(config, feature, targets)` applies the shared contract rule, so an `openai-compatible` (on-prem) model can scan. `isCardScanAvailable` is a deprecated alias kept for one release.
