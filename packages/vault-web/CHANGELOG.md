- a34d75b: Service keys for a server process (#241), agent contract 1.4 (additive, stability beta).

  - `@marinoscar/vault-contract`: the system secret type `Service Key` (`SERVICE_KEY_TYPE_NAME`; fields `service`, `key_name`, the sensitive `key` and `notes`; no website), appended last to `SYSTEM_SECRET_TYPES`, with `serviceKeyIdSchema`, `normalizeServiceKeyId` and `SERVICE_KEY_ID_PATTERN` (`./secret-types`). On `./agent`: `agentServiceKeyParamsSchema`, `agentServiceKeyResponseSchema`, `AGENT_SERVICE_KEYS_PATH`, `AGENT_SERVICE_KEY_PER_MINUTE` (120), `AGENT_SERVICE_KEY_PURPOSE` (`service_call`), the scope `AGENT_SCOPES.SERVICE_KEYS_READ` (`vault:service_keys_read`), the error code `SERVICE_KEY_AMBIGUOUS` (409), the audit action `agent.service_key.read`, the activity action `service_key` and the optional `service` and `keyName` of an activity item. `VAULT_ERROR_CODES` gains `SERVICE_KEY_AMBIGUOUS` and `SERVICE_KEY_EXISTS` (409). `AGENT_CONTRACT_VERSION` moves to `1.4` and `AGENT_CONTRACT_FEATURES` gains `SERVICE_KEYS: 'service_keys'` (always reported, after `save_login`); the snapshot is refreshed (additive).   - `@marinoscar/vault-api`: `GET /agent/v1/service-keys/:service/:name` (`AgentServiceKeysController`, permission `agent_service_keys:read`, scope `vault:service_keys_read`): the value of the caller's one `Service Key` opened to agents with that service and key name, behind the `agentAccess` kill switch, 120 a minute per owner and service, audited `agent.service_key.read` (service, key name, caller, never the value), the identical `404`, `409 SERVICE_KEY_AMBIGUOUS`. Reserved names gain the permission resource `agent_service_keys` and the audit prefix `agent.service_key.`; the metric kind `service_key`.
  - `@marinoscar/vault-web`: the "Allow your apps to use this service key" switch on a Service Key's page, the `Api` type icon, and "Service key read" rows in Agent activity (with the service and key name in the website column).
